# 予約フォームのセットアップ手順

サイトの予約フォーム（`reserve.html`）を動かすための初期設定。
全体の流れ：

```
フォーム送信（reserve.html）
    ↓
GAS ウェブアプリ（google-apps-script/reservation.gs）
    ├─ スプレッドシートに記録
    ├─ Google カレンダーに【仮】イベント作成
    ├─ 鑑定師へ通知（LINE + メール）
    └─ お客様へ受付確認メールを自動返信

未対応のまま3時間経過 → LINEに再通知（見逃し防止）
```

所要時間はだいたい30分。上から順にやれば動きます。

---

## 1. スプレッドシートを用意する

1. [Google スプレッドシート](https://sheets.new) で新規シートを作成（名前は「予約受付台帳」など何でもOK）
2. URL の `/d/` と `/edit` の間の文字列（スプレッドシートID）をメモ

例：`https://docs.google.com/spreadsheets/d/【この部分がID】/edit`

シート内のタブやヘッダー行は**作らなくてOK**（GASが自動で作ります）。

## 2. GAS プロジェクトを作る

1. [script.google.com](https://script.google.com) → 「新しいプロジェクト」
2. プロジェクト名を「予約受付」などに変更
3. `google-apps-script/reservation.gs` の中身を全部コピーして貼り付け
4. 冒頭の `CONFIG` を記入：
   - `SPREADSHEET_ID`: 手順1でメモしたID
   - `CALENDAR_ID`: 予約状況表示に使っているカレンダーのID（空ならデフォルトカレンダー）
   - `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_OWNER_USER_ID`: いったん空のままでOK（手順5で設定）
5. 関数の選択で `initSheet` を選んで実行 → 権限の承認画面が出るのですべて許可
   （ログに「シート準備OK」と出れば成功）

## 3. ウェブアプリとしてデプロイ

1. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
2. 設定：
   - 実行ユーザー: **自分**
   - アクセスできるユーザー: **全員**
3. デプロイして表示された **ウェブアプリURL** をコピー

⚠️ `reservation.gs` を修正したときは「デプロイを管理」→ 編集 → バージョン「新バージョン」で更新しないと反映されません（予約状況のGASと同じ仕様）。

## 4. サイト側にURLを設定

`js/reserve.js` の冒頭：

```js
const RESERVE_ENDPOINT = ''; // ← ここに手順3のウェブアプリURLを貼る
```

これを記入して main に push すれば、フォームが動き始めます。
（空のままの間は、フォーム欄に「準備中。LINEからご予約ください」と表示される安全設計です）

## 5. LINE通知の設定（Messaging API）

> **注意**: 以前よく使われていた「LINE Notify」は2025年3月でサービス終了しています。
> 現在は Messaging API のプッシュ送信を使うのが標準です（個人宛なら無料枠で十分）。

1. [LINE Developers コンソール](https://developers.line.biz/console/) にログイン
2. プロバイダーを作成（既にあればそれでOK）→ 「Messaging API」チャネルを新規作成
   - 名前は「予約通知Bot」など。**お客様向けの公式アカウントとは別物**として作るのがおすすめ
3. 「Messaging API設定」タブ → 一番下の「チャネルアクセストークン（長期）」を発行してコピー
   → `CONFIG.LINE_CHANNEL_ACCESS_TOKEN` に貼る
4. 「チャネル基本設定」タブ → 一番下の「あなたのユーザーID」（`U` で始まる文字列）をコピー
   → `CONFIG.LINE_OWNER_USER_ID` に貼る
5. 同じ「Messaging API設定」タブにあるQRコードを自分のLINEで読み取り、**Botを友だち追加**
   （友だち追加していないとプッシュ通知が届きません）
6. GASで `testNotify` を実行 → 自分のLINEとメールにテスト通知が届けば成功
7. **デプロイの更新を忘れずに**（手順3の⚠️参照）

## 6. 見逃し防止リマインドのトリガー設定

1. GASエディタ左側の時計アイコン（トリガー）→「トリガーを追加」
2. 設定：
   - 実行する関数: `checkUnhandledReservations`
   - イベントのソース: 時間主導型
   - 時間ベースのタイマー: **1時間おき**

これで、予約が入ってから3時間「対応状況」列が空のままだと、LINEに再通知が届きます。
（時間を変えたいときは `CONFIG.REMIND_AFTER_HOURS` を変更）

---

## 日々の運用

1. 予約が入る → LINE + メールに通知が届く
2. お客様へ確定メールを返信し、お支払いをご案内する
3. スプレッドシートの **「対応状況」列に「対応済み」と記入**（リマインド停止のため）
4. カレンダーの【仮】イベントを正式な時間に直す

## トラブルシューティング

| 症状 | 確認すること |
|------|--------------|
| フォームが「準備中」表示のまま | `js/reserve.js` の `RESERVE_ENDPOINT` が記入・push されているか |
| 送信エラーになる | デプロイ設定が「全員」になっているか／GS修正後に新バージョンでデプロイし直したか |
| LINE通知が来ない | Botを友だち追加したか／トークンとユーザーIDが正しいか／`testNotify` で切り分け |
| お客様にメールが届かない | 迷惑メールフォルダ／GASの1日あたりメール送信上限（無料アカウントは約100通/日） |
